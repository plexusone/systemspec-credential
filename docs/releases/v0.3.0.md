# Release Notes v0.3.0

Released: 2026-11-21

## Highlights

The registry can now guide whoever sets the credentials up: when each is
needed and in what order, which tool makes it, what is set up at an
issuer first, and advice on entries likely to mislead.

## Added

- **Need and order.** `need` says when a credential must exist: `launch`,
  `later`, `optional` (only when an optional part is turned on) or
  `rotation` (only while another credential rotates). `requires` lists
  what is set up first, and `Registry.SetupOrder` orders every entry after
  what it requires and depends on.
- **Provisioners.** `generation.provisioner` names the tool and command
  that make a value, who runs the command (`runBy`), and whether the tool
  stores the value. Credentials with the same command are made by one run.
  `Credential.SetUpBy` is who acts to make a value.
- **Prerequisites.** `prerequisites`, beside `credentials`, are what is
  set up at an issuer before a credential and hold no secret, such as a
  cloud project, an OAuth consent screen or a webhook endpoint. Each has
  steps or a command and says how to tell it is done.
- **Setup details.** `entitlements[].grantedBy` names what grants the
  access, `issuer.mode` is `test` or `live`, `stores[].backup` names what
  backs a store up, `rotation.secondaries` lists the credentials that
  exist only during a rotation, and `configChanges` lists the edits a
  consumer's configuration needs. `process-env` is a well-known store
  type.
- **Advice.** `Registry.Lint` reports valid entries likely to mislead: a
  provisioned credential not generated by `system`, an install that asks
  for a value its provisioner stores, no entitlements, a rotation
  procedure naming a variable nothing defines, or a rotation secondary
  not marked `need: rotation`. `validate` prints it; `--strict` fails on
  it.
- The plan lists the prerequisites still planned before its launch
  checklist, and the reference shows every new field.

## Changed

- The plan's launch checklist counts a provisioned credential as by hand
  when a person runs its command, orders by `requires` as well as
  `dependsOn`, and leaves out credentials needed only during a rotation.
- `validate` reports "N credentials, N prerequisites and N events OK".

## Upgrading

Every new field is optional, so existing registries stay valid and the
format version is still 1. Run `validate` to see the advice for yours.
